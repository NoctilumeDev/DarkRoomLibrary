# 遗留物收口门禁

本门禁位于实现、测试、验收和文档读回之后，只负责阻止失去职责的施工产物继续进入
下一阶段；它不证明业务正确、浏览器体验或真实中间件链路成立。

## 暗室藏书的保留边界

本仓库的当前截图、功能模块图、项目介绍 PPT 与三份项目 PDF 都有 README 或文档中心
作为消费方，继续承担演示、答辩或历史版本说明职责，因此属于 `KEEP`，不能仅按文件大小
或扩展名删除。覆盖率、构建目录、上传文件、日志和浏览器输出可由源码或运行重新生成，
属于工作区状态，不进入 Git。

| 状态 | 判据 | 处置 |
| --- | --- | --- |
| KEEP | 当前产品、README、文档中心或交付说明仍消费 | 留在仓库，由消费方维护 |
| ARCHIVE | 有明确历史职责，但不代表当前状态 | 保留最小材料并写明版本坐标 |
| DELETE | 可重建、无活跃引用且没有证明责任 | 从当前主线删除，历史由 Git 保存 |
| REVIEW | owner 或 consumer 不清楚 | 停止自动处置，先人工确认 |

## 自动门禁

运行 `node scripts/check-residual-hygiene.mjs`：

- 拒绝已被 `.gitignore` 定义为本地产物、却仍被 Git 跟踪的文件；
- 拒绝 `target`、`dist`、`coverage`、`test-results`、`release` 与 `node_modules` 中的生成物；
- 拒绝上传目录、临时目录、日志目录和编辑器冲突备份；
- 不限制仓库体积、图片数量或 PDF/PPT 数量，也不删除或格式化文件。

当前盘点没有发现需要从主线删除的残留物。`node_modules`、Docker 容器、Volume、本地数据库
与上传目录属于宿主或工作区状态；清理前仍须确认其中没有唯一事实，CI 不伪装成能证明这些
本机对象已被清理。
