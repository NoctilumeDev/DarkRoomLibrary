# 暗室藏书文档中心

这里保存项目设计、演示和交付验收资料。建议按目标选择阅读路线，不必从头读完所有文件。

## 三条阅读路线

### 5 分钟了解项目

1. 先读项目根目录的 [README](../README.md)。
2. 打开 [功能模块图 HTML 版](library-system-modules.html)，快速浏览完整功能。
3. 查看 [项目介绍 PPT](DarkRoomLibrary-project-overview.pptx)，理解角色、闭环、架构和技术亮点。
4. 需要了解形成过程时查看项目计划书与项目起源，需要总结工程过程时查看项目复盘。

### 15 分钟理解设计

1. 阅读 [系统设计与关键业务规则](system-design.md)。
2. 对照 [功能模块图 Mermaid 版](function-module-diagram.md)。
3. 查看 [架构审查](architecture-review.md)，理解事务、竞态、降级和未来拆分边界。
4. 查看 [部署指南](deployment.md)，理解 Compose、健康检查和多实例文件边界。
5. 需要在 Windows 单机执行高连接测试时，先读 [本地全链路测试网络边界](local-test-network-boundary.md)。
6. 查看 [最终验证报告](verification-report.md)。
7. 查看唯一的 [数据库初始化脚本](../sql/init-dark-room-library.sql)。

### 按角色验收系统

1. 使用 SQL 初始化空数据库。
2. 按 [人工验收清单](manual-acceptance-checklist.md) 准备账号与数据。
3. 依次验收 5 个角色码对应的 6 个固定权限身份、业务闭环、中间件降级、文件权限与安全边界。

## 文档维护原则

- README 只保留“是什么、怎么运行、去哪里深入阅读”。
- 系统设计文档解释“为什么这样设计”。
- 本机网络与高连接测试规范只在 `local-test-network-boundary.md` 维护，其他文档只链接，不复制诊断正文。
- 模块图只表达功能归属和关键流程，不复制接口代码。
- 验收清单描述可观察结果，不依赖实现细节。
- 项目沿革必须区分“想法起源”“课程落地条件”和“当前实现”，不伪造 Git 记录或夸大结论。
- 阶段性材料不作为最终技术版本、测试数字或项目起点的权威来源。
- 公开材料只保留明确标注的本地演示账号与统一演示密码；真实账号凭据、数据库密码、邮箱授权码、JWT 密钥和生产密钥不得入库。
- 功能、SQL 表结构、权限、依赖版本或验证结果发生变化时，应同步更新以上资料。
