# 项目沿革与 Git 说明

## 1. 项目起点

暗室藏书最初是计算机专业大二短学期的课程作业。课程开始时，学校教师发放了一份未完成的教学脚手架；其中连基础增删改查都没有形成完整可运行闭环。教师没有提供、也无法确认脚手架的原始仓库、作者和许可证。

因此，当前仓库对来源采取保守表述：

- 不把教师发放等同于获得开源授权。
- 不把后续大量重构等同于证明全部历史代码原创。
- 在来源和授权未确认前，不添加项目级 `LICENSE`。
- GitHub 公开只能解释为源码可见，不能解释为允许复制、修改或再分发。

## 2. 课程提交后的独立重构

课程作业提交后，作者在暑假继续把项目从 demo 推进为可运行、可验证、可解释的完整系统。主要工作包括：

1. 补齐借阅、归还、续借、预约、罚款和库存恢复闭环。
2. 增加书评、点赞、回复、举报、内容审核和留言附件治理。
3. 增加采购员、物流员及采购到入库的跨角色协作流程。
4. 重构权限、文件生命周期、通知补偿、操作审计和中间件降级。
5. 将 Vue 2 遗留结构迁移到 Vue 3.5，并从 Vue CLI/Jest/Babel 迁移到 Vite、Vitest 和 ESLint。
6. 将后端从 Spring Boot 2.7 迁移到 Spring Boot 3.5，并完成 Jakarta、依赖和测试适配。
7. 重写演示账号、书目、书评、留言、公告和截图素材，避免使用真实个人信息或常见样例数据。
8. 补充后端、前端、真实 API、并发一致性、浏览器诊断和数据库完整性验证。

## 3. 为什么 Git 历史从中途开始

项目早期被当作一次性课程 demo，没有立即初始化 Git。随着暑假重构范围扩大，作者才意识到需要版本控制。

仓库采用以下处理方式：

- 不伪造课程阶段或暑假早期的提交记录。
- 不回填虚构作者、提交日期或分支历史。
- 首次提交说明为“经过审查的公开基线”。
- 在 README、NOTICE 和本文件中如实说明 Git 中途加入的原因。

因此，Git 日志记录的是公开发布准备阶段，而不是项目从第一行代码开始的完整开发轨迹。

## 4. 当前公开边界

截至 2026-07-26，代码已完成系统级重构和最终回归，但脚手架来源仍未解决。发布时应保留 `NOTICE.md`，不添加项目级开源许可证，也不使用“完全原创”“可自由商用”等无法证明的表述。

后续只有在以下任一条件满足时，才适合重新评估许可证：

1. 找到原脚手架并确认其许可证允许当前发布方式。
2. 取得原作者或权利人的明确授权。
3. 对可能继承自脚手架的部分完成独立替换，并经过可追踪的来源与相似性复核。
