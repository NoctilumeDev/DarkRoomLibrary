# 暗室藏书人工验收清单

本清单用于源码交付前的最终人工验收。每项记录“通过 / 失败 / 不适用”，失败时附截图、账号、时间和操作步骤。

系统包含 5 个角色码和 6 个固定权限身份。“普通管理员”与“馆务协调员”都使用管理员角色码；馆务协调员由超级管理员任免，并通过增强能力标记获得跨管理员协调权限。

## 一、验收准备

- [ ] 使用 `scripts/setup-e2e-database.ps1 -Reset` 初始化独立的 `dark_room_library_e2e`，确认 6 个固定演示身份可以登录。
- [ ] 启动后端 `20606` 和前端 `5175`，浏览器控制台无持续报错。
- [ ] 核对演示账号角色与数据范围，再额外创建第二个读者用于并发借阅和越权测试。
- [ ] 核对虚构书目、书评、回复、留言、公告和采购物流演示数据，再准备已下架图书。
- [ ] 准备 PDF、DOCX、PNG、HTML、非法格式文件以及超过 10 MB 的文件。
- [ ] 配置真实测试邮箱；Redis、RabbitMQ 先保持关闭。

## 二、超级管理员（角色 0）

- [ ] 登录数学验证题正确时成功，错误时失败；连续失败触发登录锁定。
- [ ] 创建五类账号，修改普通管理员、采购员和物流员的角色及状态。
- [ ] 普通管理员无法修改超级管理员；超级管理员不能误删或注销自身核心账号。
- [ ] 冻结、解冻、禁言、解禁和角色变更均产生操作日志。
- [ ] 可以查看全部采购单、物流进度、跨岗位消息及已读未读状态。
- [ ] 可以进入文件管理，查看临时、已绑定、待删除文件并执行安全清理。
- [ ] 可以查看完整导出字段、流程状态和操作审计。

## 三、普通管理员（角色 1）

- [ ] 可以新增、修改、软删除和恢复图书，库存与可借数量约束正确。
- [ ] 可以维护分类和书架；存在关联数据时不能造成无效引用。
- [ ] 可以办理借阅和归还，逾期罚款、罚款封顶及库存恢复正确。
- [ ] 可以发布和修改公告，脚本内容被净化。
- [ ] 可以回复或删除留言，审核书评举报，隐藏违规内容或忽略举报。
- [ ] 只能管理权限范围内的用户，不能修改同级管理员、馆务协调员或超级管理员。
- [ ] 可以创建采购需求并与采购员沟通，但不能越权直接调度物流员。
- [ ] 不能进入超级管理员文件管理，导出结果不包含受保护字段。

## 四、读者（角色 2）

- [ ] 使用邮箱验证码注册；注册验证码不能用于重置密码，反之亦然。
- [ ] 同一邮箱重发间隔和每日次数限制生效。
- [ ] 同一规范化邮箱前三个账号可注册，第四个账号仅在验证码通过后收到“最多关联 3 个账号”的明确提示。
- [ ] 验证码错误或过期时，不因账号、署名或邮箱配额状态不同而返回可枚举信息。
- [ ] 忘记密码后可以重置并使用新密码登录，旧密码失效。
- [ ] 修改显示名称和头像后立即显示；更换联系邮箱必须验证新邮箱，原邮箱不变时不重复验证。
- [ ] 查询、分类筛选、打开详情、收藏和取消收藏均正常。
- [ ] 库存充足时借阅成功；两名读者同时抢库存为 1 的图书时仅一人成功。
- [ ] 到期前三天、无预约队列时可续借一次；其他情况均被明确拒绝。
- [ ] 无库存时可预约；达到预约上限后不能继续预约；取消预约释放名额。
- [ ] 归还后最早预约人变为已通知，非预约人不能抢走保留图书。
- [ ] 书评最新 / 最热切换、点赞、取消点赞、回复和举报形成闭环。
- [ ] 留言可附带 PDF、Word、图片和 HTML；HTML 只能下载，不能直接执行。
- [ ] 读者可以主动注销，注销后令牌失效且不能再次登录。

## 五、采购员（角色 3）

- [ ] 只看到可认领、已指派给自己或权限允许查看的采购单。
- [ ] 可以认领采购单并按合法顺序推进采购状态，不能跳过必要状态。
- [ ] 可以与创建需求的管理员沟通，消息已读未读状态正确。
- [ ] 可以分配物流员并与该物流员沟通，不能联系无关物流员。
- [ ] 不能修改用户、馆藏基础数据、审计日志或其他采购员的任务。

## 六、物流员（角色 4）

- [ ] 只看到分配给自己的物流任务。
- [ ] 可以登记承运方、运单号和备注，并按顺序更新运输、到馆、入库状态。
- [ ] 可以与对应采购员沟通，不能直接联系管理员或查看跨订单消息。
- [ ] 重复提交入库不会重复增加库存。
- [ ] 不能访问用户管理、内容审核、导出和文件管理。

## 七、跨角色业务闭环

- [ ] 管理员创建需求 -> 采购员认领 / 接单 -> 分配物流员 -> 物流到馆 -> 入库 -> 库存增加。
- [ ] 每次采购和物流状态变化均有操作者、时间、前后状态和备注记录。
- [ ] 采购取消后不能继续推进；已完成订单不能重复入库。
- [ ] 管理员与采购员、采购员与物流员的通信通道相互隔离。
- [ ] 超级管理员能查看全局留痕，普通管理员只能查看职责范围内数据。

## 八、中间件与外部服务

- [ ] Redis 关闭时验证码、登录风控和查询正常，日志明确记录降级。
- [ ] Redis 开启时验证码 TTL、登录失败计数和查询缓存正常。
- [ ] Redis 运行中断后核心借阅、登录和查询仍可继续。
- [ ] RabbitMQ 关闭时核心事务与提交后操作审计仍可执行，通知进入数据库补偿任务。
- [ ] RabbitMQ 开启时预约到货等领域事件被异步消费，通知任务最终完成；操作日志不依赖 RabbitMQ。
- [ ] 邮件不可用时通知任务保留失败原因并可重试，借还和预约结果不回滚。
- [ ] 注册、重置密码、预约到货和到期前三天提醒邮件均实际收到一次。

## 九、文件与安全

- [ ] 非法扩展名、伪造 MIME、超大文件和路径穿越文件名均被拒绝。
- [ ] 图片可以预览；PDF、Word、HTML 按权限下载；未登录不能下载私有附件。
- [ ] 删除留言、头像或图书封面后引用状态正确，仍被引用的文件不会误删。
- [ ] 临时文件超过保留期后可由超级管理员或定时任务清理。
- [ ] 公告、留言、书评、回复和采购消息中的脚本或危险标签被净化。

## 十、交付确认

- [ ] 后端 `mvn clean test` 全部通过。
- [ ] 前端 `npm run lint`、`npm run test:unit`、相关 E2E 和 `npm run build` 全部通过。
- [ ] 执行 `npm run test:e2e:registration-email`，确认验证前仅返回通用错误，验证后才返回账号、署名或邮箱配额的精确结果，并确认邮箱换绑验证与物理删除释放名额。
- [ ] 三个后端实例运行时执行 `npm run test:e2e:email-quota`，100 个同邮箱请求必须恰好 3 个成功，其余均为明确配额拒绝，不能出现 HTTP 500 或死锁。
- [ ] 生产环境变量缺失时 `prod` Profile 拒绝启动，完整配置后可以启动。
- [ ] 交付 ZIP 不包含 `node_modules`、`target`、`dist`、`test-results`、`upload`、日志或本地账号数据。
- [ ] README 中的数据库初始化、环境变量、启动和构建命令在新目录实际执行成功。
